# Product Requirements Document (PRD)
## Проект: FinanceFlow (Сервис учета личных финансов)

---

## 1. Обзор продукта (Product Overview)
**FinanceFlow** — это веб-приложение для удобного ручного учета личных финансов (доходов и расходов), разделенных по категориям. Приложение ориентировано на пользователей, предпочитающих полный контроль над своими записями без привязки банковских API.

### 1.1. Ключевые принципы
* **Быстрый ввод**: добавление транзакции должно занимать не более 5–10 секунд.
* **Тонкий клиент**: React отвечает только за отображение и ввод; валидация, расчет баланса, фильтрация и агрегация выполняются на бэкенде.
* **Современный стек**: бессерверный Node.js + распределенная SQLite-совместимая база данных Turso (libSQL).

## 3. Функциональные требования (Functional Requirements)

### 3.1. Управление транзакциями (Transactions)
* **Добавление расхода/дохода**:
  * Тип: `expense` (расход) или `income` (доход).
  * Сумма: числовое значение (поддержка копеек/центов).
  * Категория: выбор из доступных.
  * Дата: выбор даты (по умолчанию — текущая).
  * Комментарий/заметка: необязательное текстовое поле (до 255 символов).
* **Просмотр истории**:
  * Пагинация или бесконечный скролл.
  * Фильтрация по: типу (все / доход / расход), категории, диапазону дат (день, неделя, месяц, кастомный).
  * Сортировка по дате (от новых к старым).
* **Редактирование и удаление**:
  * Возможность изменить любое поле записи.
  * Мягкое или жесткое удаление с подтверждением.

### 3.2. Категории (Categories)
* **Предустановленные категории расходов**:
  * Продукты, Коммунальные услуги, Аренда жилья, Транспорт/Бензин, Развлечения/Кафе, Здоровье, Одежда, Прочее.
* **Предустановленные категории доходов**:
  * Зарплата, Подработка/Фриланс, Премия, Процент по вкладу/Дивиденды, Подарки, Прочее.
* **Кастомизация (версия 1.1)**:
  * Создание пользовательской категории с выбором типа (`income` / `expense`) и иконки/цвета.

### 3.3. Аналитика и Дашборд (Dashboard)
Все вычисления производятся на бэкенде:
* **Текущий баланс**: `Общий доход` – `Общий расход` за выбранный период.
* **Сводные карточки**: 
  * Доходы за месяц.
  * Расходы за месяц.
  * Чистая дельта (+/- к бюджету).
* **Графики**:
  * Круговая диаграмма (Pie/Donut Chart): распределение расходов по категориям.
  * Столбчатая диаграмма (Bar Chart): сравнение доходов и расходов по месяцам.

## 4. Модель данных (База данных Turso)

Схема для Drizzle ORM / SQLite:

```sql
-- Таблица категорий
CREATE TABLE categories (
  id TEXT PRIMARY KEY,           -- UUID/nanoid
  name TEXT NOT NULL,           -- Название ("Продукты", "Зарплата")
  type TEXT NOT NULL,           -- 'income' | 'expense'
  color TEXT,                   -- HEX-код для графиков ('#10B981')
  icon TEXT                     -- Имя иконки ('shopping-cart')
);

-- Таблица транзакций
CREATE TABLE transactions (
  id TEXT PRIMARY KEY,           -- UUID/nanoid
  amount REAL NOT NULL,          -- Сумма (например, 1250.50)
  type TEXT NOT NULL,           -- 'income' | 'expense'
  category_id TEXT NOT NULL,    -- Связь с категорией
  date TEXT NOT NULL,           -- ISO строка (YYYY-MM-DD или ISO 8601)
  comment TEXT,                 -- Примечание
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (category_id) REFERENCES categories (id) ON DELETE RESTRICT
);
```

## 5. Спецификация Backend API

Базовый путь: `/api`

### 5.1. Транзакции
* `GET /api/transactions`
  * **Query-параметры**: `from`, `to`, `type`, `categoryId`, `page`, `limit`
  * **Ответ**: `{ data: Transaction[], total: number, page: number }`
* `POST /api/transactions`
  * **Тело**: `{ amount: number, type: 'income' | 'expense', categoryId: string, date: string, comment?: string }`
  * **Валидация**: `amount > 0`, валидная дата, существующий `categoryId`.
* `PUT /api/transactions/:id`
  * **Тело**: Обновленные поля транзакции.
* `DELETE /api/transactions/:id`
  * **Ответ**: `{ success: true }`

### 5.2. Категории
* `GET /api/categories` — список всех категорий (с возможностью фильтрации по `?type=income|expense`).
* `POST /api/categories` — создание новой категории.

### 5.3. Аналитика и Статистика
* `GET /api/analytics/summary?month=2026-10`
  * **Ответ**:
    ```json
    {
      "totalIncome": 250000.00,
      "totalExpense": 115000.00,
      "balance": 135000.00,
      "byCategory": [
        { "categoryName": "Продукты", "amount": 45000.00, "percent": 39.1 },
        { "categoryName": "Аренда", "amount": 50000.00, "percent": 43.5 }
      ]
    }
    ```

## 6. Нефункциональные требования

1. **Безопасность конфигурации**:
   * Токены подключения к Turso (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`) должны храниться строго в Vercel Environment Variables и `.env.local` на локальной машине.
2. **Производительность**:
   * Время ответа API на запросы чтения/записи не должно превышать 300–500 мс (Turso Edge DB обеспечивает быстрый отклик).
   * Bundle size клиентской части React — оптимизирован через Vite (code splitting).
3. **Адаптивность (Mobile-First)**:
   * Интерфейс должен быть оптимизирован под мобильные экраны (смартфоны), так как ручной ввод чеков чаще всего происходит на ходу с телефона.
4. **Валидация данных**:
   * На бэкенде обязательно использовать библиотеку валидации (например, **Zod**) перед выполнением запросов к базе.

## 7. План реализации (Roadmap)

### Этап 1: Инфраструктура и База Данных
1. Инициализация репозитория на GitHub.
2. Создание базы данных в Turso CLI / Turso Dashboard.
3. Настройка схемы данных через Drizzle ORM.
4. Написание сидов (seed script) для начального наполнения категорий.

### Этап 2: Backend API
1. Настройка маршрутов в `/api`.
2. Реализация CRUD для транзакций и категорий.
3. Реализация эндпоинта сводной аналитики (расчет баланса и группировка сумм).
4. Подключение Zod-валидации.

### Этап 3: Frontend разработка
1. Инициализация Vite + React + Tailwind CSS.
2. Верстка UI компонентов: модальное окно добавления расхода/дохода, селектор категорий, инпут суммы.
3. Разработка дашборда с графиками (Recharts).
4. Список истории транзакций с фильтрами.
5. Интеграция с API через React Query.

### Этап 4: Развертывание и тестирование
1. Настройка проекта в панели Vercel.
2. Добавление переменных окружения (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`).
3. Тестирование сквозных сценариев (End-to-End).
